# Задание 1. Анализ и планирование


### 1. Описание функциональности монолитного приложения

**Управление отоплением:**

- Пользователь может удалённо управлять отоплением в доме через веб-интерфейс.
- Система отправляет команды управления отоплением от сервера к модулю управления отоплением.
- Подключение модуля отопления выполняется только через выезд специалиста компании.
- Пользователь не может самостоятельно подключить новый датчик или реле к системе.

**Мониторинг температуры:**

- Пользователь может проверить текущую температуру в доме.
- Сервер получает данные о температуре синхронным запросом к датчику.
- Температурные данные хранятся в PostgreSQL.
- Система не поддерживает реактивное получение телеметрии от устройств.

### 2. Анализ архитектуры монолитного приложения

Текущее приложение реализовано как монолит на Go с единой базой данных PostgreSQL.

Основные особенности текущей архитектуры:

- Все функции находятся в одном монолитном приложении.
- Используется одна общая база данных PostgreSQL.
- Взаимодействие между сервером и устройствами полностью синхронное.
- Асинхронные вызовы, брокеры сообщений и реактивное взаимодействие отсутствуют.
- Управление устройствами инициируется сервером.
- Получение температуры также выполняется через запрос сервера к датчику.
- Подключение устройств не является self-service процессом и требует участия специалиста.
- Система поддерживает только управление отоплением и мониторинг температуры.

### **4. Проблемы монолитного решения**

- Монолит сложно масштабировать по отдельным функциональным направлениям: отопление, свет, ворота, видеонаблюдение и сценарии развиваются с разной нагрузкой и разной скоростью.
- Единая кодовая база увеличивает риск при накатке новых версий: изменение логики отопления может повлиять на другие части системы.
- Отсутствует self-service подключение устройств, поэтому масштабирование на большое количество домов или изменения в логике работы существующего дома требует слишком много ручной работы специалистов.
- Синхронное взаимодействие с устройствами плохо подходит для телеметрии и событий умного дома, т.к. серверу приходится постоянно опрашивать устройства, это создаёт большую нагрузку на систему в целом. Кроме того, о каких-то важных собятиях, например, открытие ворот сервер узнает с задержкой и отреагирует позже, чем ожидается (например, включение света)
- Система не готова к подключению устройств партнёров и будущих неизвестных типов датчиков.
- Единая база данных создаёт жёсткую связанность между функциональными областями.
- Отсутствие асинхронной обработки усложняет сценарии автоматизации
- Команде из пяти разработчиков будет трудно параллельно развивать разные направления внутри одного монолита.

# Задание 5. Работа с docker и docker-compose

Перейдите в apps.

Там находится приложение-монолит для работы с датчиками температуры. В README.md описано как запустить решение.

Вам нужно:

1) сделать простое приложение temperature-api на любом удобном для вас языке программирования, которое при запросе /temperature?location= будет отдавать рандомное значение температуры.

Locations - название комнаты, sensorId - идентификатор названия комнаты

```
	// If no location is provided, use a default based on sensor ID
	if location == "" {
		switch sensorID {
		case "1":
			location = "Living Room"
		case "2":
			location = "Bedroom"
		case "3":
			location = "Kitchen"
		default:
			location = "Unknown"
		}
	}

	// If no sensor ID is provided, generate one based on location
	if sensorID == "" {
		switch location {
		case "Living Room":
			sensorID = "1"
		case "Bedroom":
			sensorID = "2"
		case "Kitchen":
			sensorID = "3"
		default:
			sensorID = "0"
		}
	}
```

2) Приложение следует упаковать в Docker и добавить в docker-compose. Порт по умолчанию должен быть 8081

3) Кроме того для smart_home приложения требуется база данных - добавьте в docker-compose файл настройки для запуска postgres с указанием скрипта инициализации ./smart_home/init.sql

Для проверки можно использовать Postman коллекцию smarthome-api.postman_collection.json и вызвать:

- Create Sensor
- Get All Sensors
